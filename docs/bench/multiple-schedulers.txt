Multiple io_uring schedulers in blobcache

Default: one unpinned ring. Each entry in WithSchedulerCPUs creates one ring;
-1 leaves its coordinator unpinned. WithWriteSchedulers(n) reserves the first
n rings for writes and cleanup; remaining rings serve reads. With n=0, all
rings serve both. At least one ring must serve reads. CPU lists are copied.

Reads are ALWAYS unbudgeted. WithIOBudget controls WRITE admission only:
1.5 ms by default, shared across all rings; zero disables it. Ring capacity and
operation ordering still apply to reads. Dio's WithoutReadIOBudget option is
applied to every blobcache scheduler, including shared single-ring schedulers.

Dio shares configuration and atomic accounting in one policy:

    policy := iosched.NewDiskPolicy(iosched.WithLatencyGoal(1500*time.Microsecond),
        iosched.WithoutReadIOBudget(), iosched.WithRejectWriteBacklog(2_000_000_000))
    // Pass iosched.WithDiskPolicy(policy) to each ring serving that device.

NewDiskPolicy accepts DiskPolicyOption values only. Ring depth and CPU options
belong to NewURingScheduler. Submit only checks the policy's rejection limits
(queue depth, backlog bytes, backlog pause); a closed limit returns ErrRejected
immediately, with no ticket or executed operations. The coordinator charges the
chain's counts and bytes when it accepts the work. The time allowance does not
reject: work that does not fit waits in its coordinator's ready queue until
completions return allowance. Ticket completion returns the remaining charges.

Requested comparison:

    WithSchedulerCPUs(-1) // baseline: reads unbudgeted; writes 1.5 ms

    WithSchedulerCPUs(-1, -1, -1, -1), WithWriteSchedulers(1), WithIOBudget(0)
    // four unpinned rings: one write, three read, all unbudgeted

    WithSchedulerCPUs(2, 3, 4, 5), WithWriteSchedulers(1), WithIOBudget(0)
    // four pinned rings: CPU 2 writes, CPUs 3/4/5 read, all unbudgeted

Multiple rings or a pinned ring require io_uring; Open returns setup errors.
Affinity follows dio's best-effort policy and logs pinning failures. The option
pins coordinators; kernel workers may inherit those masks. SQPOLL is not enabled.
Use allowed CPUs on the actual host and inspect both coordinator and worker masks.

Routing and lifetime

Readers and writers select a ring round-robin at construction and retain it
through streaming batches and close/error cleanup. Virtual descriptors belong
to their ring. A reader may choose any read ring regardless of the writer's ring.
Memory hits do not select a ring. Memory ownership and reclamation are unchanged.

Open -> I/O -> close chains stay on their owning ring. The final data write,
virtual descriptor close, and index write stay chained together. Put waits for
that chain and requested index sync before publication. Index reuse is gated by
pending reservations and wipe completion. Stop users and close readers/writers
before Cache.Close; Close drains cleanup and closes every ring before shared
files and memory. Topology is fixed at Open. WithRingDepth applies per ring;
each ring has its own 1024 virtual-file slots. An open external reader or
writer holds one slot from its first I/O until its final I/O or Close; a full
table returns ErrNoDescriptors (wrapping ENFILE). The default single ring falls
back to dio's POSIX scheduler without io_uring; it emulates the virtual-file
table in userspace with the same allocation and ENFILE semantics.

A direct read can complete with EAGAIN on XFS (xfs_ilock_nowait fails mid-read
and io_uring does not reissue from the completion context). Readers resubmit
the unconsumed refill up to 8 times, backing off from 20 us to about 5 ms in
total, then return the error. Writes are not retried.

Measurement

    BLOBCACHE_SCHEDULER_CPUS=-1    comma-separated CPUs; -1 is unpinned
    BLOBCACHE_WRITE_SCHEDULERS=0   first N rings dedicated to writes
    BLOBCACHE_RING_DEPTH=256      entries per ring
    BLOBCACHE_IO_BUDGET_US=1500    WRITE budget for the disk; 0 disables

IO-SCHEDULER logs roles, actual backend, requested CPU, read-io-budget=0s, and
write-io-budget (the disk-wide allowance, not an independent ring quota). DIO-DISK records the shared outstanding admission charges.
Cache.IOSchedulerStats exposes the same configuration.

The fresh 256 GiB workload uses:
    BLOBCACHE_DISK_GIB=64 BLOBCACHE_CACHE_MEMORY_MB=16384
    BLOBCACHE_CHECKSUMS=0 BLOBCACHE_VERIFY_CHECKSUMS=1
    BLOBCACHE_DURABLE_INDEX=1 BLOBCACHE_FAIL_ON_ERROR=1
    go test -run '^$' -bench '^BenchmarkBlobCache/steady-1GBps$' \
        -cpu=32 -benchtime=238483x -timeout=15m -benchmem

Rsync both source trees and compile on the host. Use fresh cache directories and
identical CPU/heap/block/mutex profiles, vmstat/iostat/pidstat/mpstat, affinity,
per-ring queues, hardware counters, perf sampling, and EAGAIN completion traces.
The paced workload measures CPU and latency at its offered rate, not saturation
throughput. Compare errors and evictions as well as performance. The baseline
versus four-ring comparison changes write budgeting as well as topology; the
pinned versus unpinned four-ring comparison changes only requested affinity.

Queue rejection and variable bursts

WithRejectWriteQueueDepth(n) and WithRejectWriteBacklog(bytes) limit outstanding
dio work across all schedulers on the disk. The matching read options are available but default to
disabled. All limits default to zero (unlimited). Outstanding includes staged, waiting, ready and in-flight work through chain completion,
including durable sync. Each read/write operation counts toward its class's depth;
bytes sum every read/write buffer in that class. Bytes are I/O lengths, not unique allocated memory.

Exceeding either limit rejects the entire submission with ErrRejected before
any operation executes. Even an otherwise empty scheduler rejects an oversized
submission. Callers retain buffers and file descriptors; normal reader/writer
Close is required after a rejection. Blobcache leaves a rejected fill unpublished
and cleans up any earlier streaming writes. Index wipes use MustAdmit to bypass
all admission limits so eviction and slot reuse can finish. They are not
charged and do not appear in DiskPolicy stats, so actual device backlog can
exceed a cap while maintenance runs.

    BLOBCACHE_REJECT_WRITE_QUEUE_DEPTH=0
    BLOBCACHE_REJECT_WRITE_BACKLOG_BYTES=0
    BLOBCACHE_REJECT_READ_QUEUE_DEPTH=0
    BLOBCACHE_REJECT_READ_BACKLOG_BYTES=0

Both streams start a goroutine at each scheduled arrival. There are no harness
worker queues, fixed concurrency limits, or retries of ErrRejected or ErrBusy.
DIO-DISK reports current shared operation counts, bytes and modeled service
cost. Request outcome counters in the harness report rejections. Per-ring queue
statistics and lifetime peaks have been removed from the scheduler hot path.
REJECTIONS reports dio rejections; CACHE-BUSY separately reports allocator or
record-reuse pressure. Rejected bytes are the full offered payload of the failed
fill; a streaming fill may already have written part of its data. Successful
request throughput counts only published fills. Start-delay histograms measure
scheduled arrival to beginning the cache call, including runtime scheduling.
BURST-DRAIN includes every terminal write outcome, including rejection.

prepareSubmission copies the flat operand chain, checks internal scheduler
limits, and collects the operation counts, bytes and modeled service costs. Submit claims shared counters atomically;
failed admission rolls back every claim, including the read charge if a mixed
chain fails write admission. Disk statistics include staged work and retain charges through ticket completion. Fields are observed
independently. Harness histograms are aggregated after each request finishes;
that statistics lock does not control admission.

The bursty-variable case keeps the same seeded payload and independent read
generation, but chooses a background byte rate uniformly for each cycle. The
background is not raised to force a near-saturation cycle average. Defaults:

    BLOBCACHE_BACKGROUND_MIN_MBPS=750      decimal MB/s
    BLOBCACHE_BACKGROUND_MAX_MBPS=1225
    BLOBCACHE_BURST_MBPS=2000
    BLOBCACHE_BURST_MIN_MS=2000
    BLOBCACHE_BURST_MAX_MS=4000
    BLOBCACHE_BURST_CYCLE_MIN_MS=12000      includes background plus burst
    BLOBCACHE_BURST_CYCLE_MAX_MS=18000

These ranges have an expected long-run offered average of 1.19 GB/s; the
finite seeded plan reports its actual offered average.

    go test -run '^$' -bench '^BenchmarkBlobCache/bursty-variable$' ...

Keep the bursty-1p2GBps case to reproduce the older offered arrival trace. Both cases report one
overall set of metrics plus burst count/duration and backlog snapshots, with
no burst/quiet latency classification.

For the current comparison, run one shared ring and eight rings with one
write ring and seven read rings, all unpinned. Both use a 1.5 ms write budget
and a 2,000,000,000-byte write backlog cap. Operation-count and read rejection
limits remain disabled. Ring depth is 256 and GOMAXPROCS is 32.

Use 700,000 measured writes (about 800 GB offered), the existing roughly 32 GB
memory warmup, a 400 GiB disk target and 16 GiB slabs. Read quotas are 85% once,
10% twice, and 5% uniformly from 3 through 10; all read ages remain 100 ms–2 min.
BLOBCACHE_CPU_PROFILE records CPU samples only during the measured phase.

The starting aggregate backlog limit is 2 GB (decimal), with operation-count
limits disabled. At 1.2 GB/s write throughput, 2 GB drains in about 1.67 seconds
after arrivals stop, or 4.44 seconds with continuing 750 MB/s arrivals. In
general, drain time is backlog / (completed-write rate - arrival rate).
Both can be unpinned initially. Read rejection stays disabled. All rings now
share one dio DiskPolicy: bandwidth/IOPS describe
the disk; the service-time allowance and rejection limits apply to combined
work. An oversized operation can proceed only when its class is idle across
all rings sharing that policy. Cache.IODiskStats reports the shared outstanding charges. Compare read/write latency and delivered bytes
alongside rejection counts and rejected bytes; fewer accepted requests alone
can make latency look better.
